# Code review 005 — ST-007 и ST-008 (internal/apply)

## ST-007 — approve с первой итерации

Monitor подтвердил мутациями: перестановка порядка в `BuildPlan` валит VC2; возврат `guardWriteTarget` к восстановлению корня из пути валит новый регрессионный тест. Snapshot читается один раз, EINVAL не ретраится, два молчания AC-16 — разные пути кода.

Заодно закрыт хвост ST-002: `WriteKnob` и `guardWriteTarget` получили явный корень вместо восстановления из переданного пути. Поддельный pod-каталог, вложенный внутрь настоящего, больше не проходит.

## ST-008 — две итерации

Итерация 1, находка MEDIUM: тесты VC3 не ловили кеш веса, спрятанный **вне** структуры `Applier`. Monitor доказал мутацией — пакетная переменная с ключом по UID пода прошла весь пакет незамеченной, включая структурную проверку через `reflect` и поведенческий тест. Причина: каждый тест брал новый UID и вызывал `Revert` один раз, поэтому кеш всегда промахивался.

Это ровно риск №1 подзадачи по блюпринту, и сетка его не держала.

Итерация 2: добавлен чёрно-ящичный `TestVC3RepeatedRevertUsesLiveSpec` — два вызова `Revert` для одного UID со сменой `requests.cpu` между ними. Проверено **двумя независимыми мутациями**: Actor внедрял кеш своим способом, я — своим (пакетная мапа плюс memo-хелпер). Оба раза тест падает с `cpu.weight = "20", want "79"`. Теперь кеш ловится независимо от места, где спрятан.

Заодно `test_vc2_idle_write_failure_skips_weight_write` стал табличным по классам ошибок: EINVAL, ErrCgroupGone, ErrNotPodCgroup, generic.
