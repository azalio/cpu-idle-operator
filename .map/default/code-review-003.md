# Code review 003 — ST-004 (internal/qos)

Monitor итерация 1: valid=false, recommendation=revise. Две находки HIGH, обе подтверждены.

## HIGH-1 — RestoreWeight не суммирует native sidecar

`internal/qos/weight.go`, `effectiveMilliCPURequest`: все `spec.InitContainers` обрабатываются одинаково через `max`, поле `RestartPolicy` не читается вовсе.

Реальное правило kubelet (сверено по `k8s.io/kubectl@v0.34.0/pkg/util/resource/resource.go`): init-контейнер с `RestartPolicy == Always` — это native sidecar, он работает конкурентно весь жизненный цикл пода и **суммируется** с обычными контейнерами. Обычный последовательный init сравнивается через `max`, но уже с учётом накопленных sidecar.

Сценарий отказа: main 100m + sidecar 200m. Kubelet даст 300m, код даст `max(100,200)=200m`. После снятия idle агент восстановит заниженный вес — тихая деградация справедливости распределения CPU, ровно тот класс дефекта, ради которого подзадача существует. Кластер стенда 1.36.3, sidecar GA с 1.29.

Довод «implementation_hint говорит sum-regular/max-init» не покрывает разрыв: описание подзадачи прямо требует «включая init/sidecar по правилам kubelet», а в `deferred_yagni` такого сужения нет.

## HIGH-2 — тест на знаменатель не ловит регрессию, хотя комментарий утверждает обратное

Мутация `262142 → 262140` на изолированной копии не завалила ни один тест.

Расчёт подтверждает: на всех точках таблицы (0, 1, 100, 500, 1000, 2000, 4000 милли) оба знаменателя дают одинаковый результат. Первое расхождение — на 1539m: 60 против 61.

**Это моя ошибка в постановке.** Я сказала Actor'у, что точка 1000m→39 ловит неверный знаменатель там, где 500m не ловит. Это неверно. Комментарий в тесте воспроизводит моё утверждение дословно, поэтому в коде теперь стоит ложное обоснование.

Единственная защита от повторения уже случившегося инцидента (неверный знаменатель в первой версии `hack/stand-probe.sh`) не работает.

Отдельно: в `hack/stand-probe.sh` функция `expected_weight` проверяется только на 500m и страдает тем же — но это файл закрытой подзадачи ST-014, правка туда вне скоупа ST-004. Зафиксировано как хвост.
